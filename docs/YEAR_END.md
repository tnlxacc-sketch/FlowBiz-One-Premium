# FlowStock: ปิดปีและเริ่มปีใหม่

การล้างข้อมูลปีเก่าต้องทำหลังสิ้นปีและก่อนสร้างธุรกรรมปีใหม่เท่านั้น ระบบปฏิเสธเมื่อมี Order/Invoice/รับสินค้า/เที่ยวส่ง/Stock movement ของปีใหม่ งานค้าง หรือ Stock ที่ถูกจัดสรรไว้ การล้างธุรกรรมจะเก็บ Master, Users, Settings, Monthly Cost และ Audit Log; Stock คงเหลือถูกยกเป็น Opening Stock ต้นปี พร้อม Audit อ้างอิง SHA-256 ของไฟล์สำรอง

## สำรองและตรวจสอบ

1. หยุดการบันทึกธุรกรรมของบริษัทระหว่างสำรองจนกว่าจะจบการเริ่มปีใหม่ แจ้งผู้ใช้ล่วงหน้า
2. ใช้เครื่องที่มี Node.js 20+, `pg_dump`, `pg_restore`, `psql`, `tar` และพื้นที่เพียงพอ กำหนดตัวแปรต่อไปนี้บนเครื่องผู้ดูแลฐานข้อมูล (ไม่เก็บความลับใน Git):

   - `DATABASE_URL`: PostgreSQL connection string ที่อ่านทั้งฐานข้อมูลและเขียน schema `private` ได้
   - `SUPABASE_URL`: Project URL
   - `SUPABASE_SERVICE_ROLE_KEY`: ใช้ดาวน์โหลด POD จาก private Storage
   - `COMPANY_ID`: UUID ของบริษัท
   - `CLOSED_YEAR`: ปี ค.ศ. ที่ต้องปิด เช่น `2026`
   - `BACKUP_DIRECTORY`: โฟลเดอร์บนพื้นที่สำรองที่จำกัดสิทธิ์

3. รัน `node scripts/backup-year.mjs` ที่โฟลเดอร์โปรเจกต์ เครื่องมือจะ `pg_dump` **ทั้งฐานข้อมูล** (รวม Auth, Master, Audit และ schema), ตรวจ `pg_restore --list`, ดาวน์โหลดไฟล์ POD ของบริษัท, ทำ manifest พร้อม SHA-256 ของแต่ละไฟล์, สร้างและตรวจ `.tar.gz`, เทียบจำนวน POD metadata และ Audit ก่อน/หลัง แล้วลงทะเบียน hash ใน `private.year_end_backups` ด้วยสิทธิ์ผู้ดูแลฐานข้อมูล
4. ย้ายไฟล์ `.tar.gz` ไปยังพื้นที่สำรองนอกเครื่องและตรวจ SHA-256 อีกครั้ง เก็บไฟล์อย่างปลอดภัยเพราะฐานข้อมูลอาจมีข้อมูลของบริษัทอื่นด้วย ทดสอบกู้คืนในฐานข้อมูลแยกก่อนใช้จริง
5. Admin ของบริษัทเปิดเมนู **สำรอง / เริ่มปีใหม่** กรอกปีที่ปิด รหัสบริษัท SHA-256 ที่ลงทะเบียนแล้ว และเหตุผล ระบบจะล้างธุรกรรมในธุรกรรมเดียวและสร้าง Stock ยกมา ตลอดจนบันทึก Audit สำหรับข้อมูลจำนวนมาก ให้ผู้ดูแลฐานข้อมูลใช้ `node scripts/rollover-year.mjs` ผ่าน PostgreSQL โดยตรงแทน HTTP เพื่อหลีกเลี่ยง timeout ต้องตั้ง `DATABASE_URL`, `ADMIN_USER_ID` (UUID ของ Company Admin), `COMPANY_CODE`, `CLOSED_YEAR`, `ARCHIVE_SHA256` และ `ROLLOVER_REASON` บนเครื่องก่อนรัน

เมนู CSV ใน Reports ใช้ดูรายการล่าสุดเท่านั้น ไม่ใช่ไฟล์สำรองข้อมูลทั้งปี หากข้อมูลเปลี่ยนหลังสำรอง ระบบปฏิเสธการเริ่มปีใหม่และต้องสำรองใหม่ หากไม่มี Backup ที่ลงทะเบียน ระบบปฏิเสธการล้างข้อมูลจริง ห้ามใช้ปุ่มล้างข้อมูล Demo สำหรับบริษัทจริง

**ข้อจำกัด:** เครื่องมือสำรองต้องรันโดยผู้ดูแลฐานข้อมูลที่มี credentials; เว็บเบราว์เซอร์ไม่สามารถสำรองฐานข้อมูลและ Storage หลายแสนรายการอย่างเชื่อถือได้ ขณะนี้ยังไม่ได้ทดสอบกู้คืนและทดสอบการล้างจริงกับข้อมูล 500,000 รายการ ต้องทดสอบในฐานข้อมูลสำเนาก่อนใช้กับปีที่มีข้อมูลจริง


## Restore rehearsal

ก่อน Production Go-live และหลังมีการเปลี่ยนโครงสร้างสำคัญ ให้ Restore archive ล่าสุดไปยัง Test Environment แยกด้วย `node scripts/restore-rehearsal.mjs` แล้วตรวจให้หน้า Admin แสดง `DR READY` ก่อนอนุมัติ Go-live ห้ามชี้ Restore target ไปยัง Production project.
